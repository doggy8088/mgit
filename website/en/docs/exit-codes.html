Exit codes and environment

How the run reports success, and how the environment overrides it

On this page

Exit codesEnvironment variables

Exit codes

CodeMeaning
0Every repository succeeded (or nothing was found with --allow-empty)
1A repository failed, or no repository was found
2The command line could not be parsed
127git could not be started
130Interrupted with Ctrl+C (SIGINT / SIGTERM)
otherThe exit code of the first failing git invocation, reported unchanged

Results are aggregated: every repository runs by default (--keep-going) and the first failing exit code becomes the exit code of mgit. The summary goes to standard error, so standard output stays clean.

Environment variables

VariableDescription
MGIT_GITName or path of the git executable (default git)
MGIT_COLORauto, always or never; overrides the terminal detection
MGIT_ASCII1 forces ASCII glyphs, 0 forces Unicode glyphs
NO_COLORDisables color when set to a non empty value (no-color.org)
CLICOLOR_FORCEForces color when set to a non empty value other than 0
CLICOLOR0 disables color
MGIT_VERSIONRelease to install, for example 2.0.0 (default: the latest one)
MGIT_INSTALL_DIRInstall directory used by the installers
MGIT_DOWNLOAD_BASEBase URL the installers download from (used by the tests)

Precedence: command line → MGIT_* → CLICOLOR_FORCE → NO_COLOR → terminal detection.

NO_COLOR=1 mgit status# force color off
MGIT_ASCII=0 mgit# keep Unicode glyphs even under LANG=C
MGIT_GIT=/usr/local/bin/git mgit fetch# point at a specific git
