Options

The thirteen options, the parsing rule, and everyday examples

The parsing rule

mgit only claims the options it documents. Anything it does not recognise (-c, --git-dir, …) goes straight to git, the same transparent behaviour the old scripts had. When the first argument of a command happens to share a name with an option (--version), separate it with --.

OptionDescription
-h, --helpPrint the help and exit
-V, --versionPrint the version and exit
-l, --listList the repositories that were found (one absolute path per line)
-d, --depth <N>How many directory levels to search, default 1
-q, --quietSuppress the per repository header
--color <WHEN>auto (default), always or never
--no-colorThe same as --color=never
--asciiASCII only glyphs, no emoji
--summaryAlways print the closing summary
-k, --keep-goingContinue after a failing repository (default)
--fail-fastStop at the first repository that fails
--allow-emptyExit with 0 when no repository was found
--Everything that follows is passed to git verbatim

Everyday examples

# also update repositories one level deepermgit --depth 2 fetch
# which directories will be touched?mgit --list
# one line of history per repositorymgit -q log --oneline -n 1
# stop at the first conflictmgit --fail-fast pull
# no colors when writing into a file or CI logmgit --color=never status
# ASCII only output for legacy Windows consolesmgit --ascii
# git's own global options still workmgit -c core.pager=cat status
Separator

mgit's own options only apply before the first argument that is not its own; everything after that goes to git.
