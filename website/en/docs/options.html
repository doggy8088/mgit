The parsing rule

Only the options in this manual belong to mgit; anything else (-c, --git-dir, …) goes straight to git. When the first argument collides with an option name (--version), separate it with --.

OptionDescription
-h, --helpPrint the help and exit
-V, --versionPrint the version and exit
-l, --listList the repositories that were found (one absolute path per line)
-d, --depth <N>How many directory levels to search, default 1
-q, --quietSuppress the per repository header
--color <WHEN>auto (default), always or never
--no-colorThe same as --color=never
--asciiASCII only glyphs, no emoji
--summaryAlways print the closing summary
-k, --keep-goingContinue after a failing repository (default)
--fail-fastStop at the first repository that fails
--allow-emptyExit with 0 when no repository was found
--Everything that follows is passed to git verbatim

Everyday examples

mgit --depth 2 fetch# also update repositories one level deeper
mgit --list# which directories will be touched?
mgit -q log --oneline -n 1# one line of history per repository
mgit --fail-fast pull# stop at the first conflict
mgit --color=never status# no colors when writing into a file or CI log
mgit --ascii# ASCII only output for legacy Windows consoles
mgit -c core.pager=cat status# git's own global options still work
Separator

mgit's own options only apply before the first argument that is not its own; everything after that goes to git.
