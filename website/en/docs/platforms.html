Behaviour on all three systems

SituationBehaviour
Output redirected (pipe, file, CI log)Color is switched off automatically; plain text only
Windows cmd.exe / PowerShell 5.1Tries to enable virtual terminal (VT) mode so ANSI color works; falls back to no color when it cannot
Windows console code page is not UTF-8Switches to ASCII glyphs (Folder: … | Branch: …) so no emoji turns into noise
PowerShell 7, Windows Terminal, macOS, LinuxUses Unicode glyphs (📂, │, ✗, ─)
POSIX locale that is not UTF-8 (LANG=C)Switches to ASCII glyphs; MGIT_ASCII=0 forces Unicode back
NO_COLOR / CLICOLOR_FORCEFollows the community conventions (see the environment chapter)
mgit … | headRestores the default SIGPIPE behaviour and exits quietly instead of panicking
git on WindowsFound through PATH (including PATHEXT); MGIT_GIT takes a full path

Two Windows details

  • VT mode is requested at start-up; when it cannot be enabled, color is switched off instead of printing escapes a console cannot render.
  • A console code page that is not UTF-8 switches to ASCII glyphs; MGIT_ASCII=0 overrides it.

Pipes

mgit … | head restores the default SIGPIPE behaviour: the run ends quietly when the pipe closes, with no panic message.
