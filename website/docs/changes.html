與 1.0（Shell 版）的差異版本與發行

與 1.0（Shell 版）的差異

舊版是 mgit（Bash）與 mgit.ps1（PowerShell）兩份腳本，原檔封存在 archive/。新版的原則是預設行為與輸出格式盡量不變，但把明顯的缺陷修掉。

項目1.0.02.x
執行形式Bash 腳本 + PowerShell 腳本（各自維護）單一 Rust 二進位檔，跨平台共用同一組測試
預設指令git status -s相同
輸出格式80 個 =、📂 Folder: … │ Branch: …相同，再加上可切換的 ASCII 模式
找不到儲存庫完全靜默、結束代碼 0印出警告並以 1 結束（--allow-empty 回復舊行為）
結束代碼多儲存庫模式永遠回傳 0彙總結果，回傳第一個失敗的結束代碼
選項無，所有參數都給 git新增 --list、--depth、--quiet、--color、--ascii、--summary、--fail-fast、--allow-empty
顏色一律輸出 ANSI 跳脫序列依終端機能力自動決定，並支援 NO_COLOR／CLICOLOR_FORCE
網頁與安裝腳本public/、install.sh、install.ps1 直接提供腳本安裝腳本改為下載並驗證官方發行檔

版本與發行

版本以 Cargo.toml 為單一來源，遵循 SemVer；Cargo.toml、Cargo.lock、npm/package.json、CHANGELOG.md 與 git 標籤必須一致。

scripts/bump-version.sh patch# 2.0.2 → 2.0.3（同步三個檔案）
git tag -a v2.0.3 -m "mgit 2.0.3" && git push origin HEAD v2.0.3# 推送標籤即觸發發行
  • 每個版本都必須先在 CHANGELOG.md 建立 ## [X.Y.Z] - YYYY-MM-DD 區段；GitHub Release 的說明就是該區段。
  • Release workflow 驗證版本一致性、跑完整測試、為 8 個目標建置並產生檢查碼，最後釋出到 GitHub Releases（含 SHA256SUMS.txt）。
  • 接著 Publish to npm workflow 用 trusted publishing 發佈 @willh/mgit，不需要任何 token。
發行後驗證

官方安裝腳本會在三平台安裝已發佈的版本做最終驗證；npm 版本附 provenance 簽章。
