它怎麼找儲存庫

預設只找第一層；結果依名稱排序，三個作業系統一致。--list 先看清楚會動到誰。

  1. 從當前目錄往下找，預設只找第一層（--depth 可以再往下）。
  2. 目錄裡有 .git 目錄或 .git 檔案都算儲存庫，所以 git worktree 與 submodule 都認得。
  3. 找到儲存庫之後不再往該儲存庫裡面走，submodule 或 vendored 的專案不會被重複算進來。
  4. symlink 會跟進，而且以「看到的名字」為準；同時走訪過的實際目錄只進入一次，連結迴圈不會無限迴圈。
  5. 結果依名稱排序（忽略大小寫），排序在 macOS、Linux、Windows 完全一致。
  6. 一個都沒找到時會警告並以 1 結束（--allow-empty 可回復舊行為）；若當前目錄本身就是儲存庫，就直接在該目錄執行 git。

紙尾的結算

失敗的那次把出事的 repo 與代碼寫進摘要（✗ web-console (exit code 128)），整體以第一個失敗的代碼收尾。

結束代碼mgit 2.0.2
Code意義
0全部成功（或搭配 --allow-empty 找不到任何儲存庫）
1有儲存庫失敗，或一個儲存庫都找不到
2命令列參數無法解析
127找不到或無法執行 git
130被 Ctrl+C 中斷（SIGINT／SIGTERM）
其他第一個失敗的 git 指令回傳什麼，mgit 就回傳什麼

安裝

單一 Rust 二進位、零執行期相依；官方安裝腳本先驗 SHA-256 再安裝。

macOS · LinuxPOSIX sh，自動偵測作業系統與 CPU 架構、驗證 SHA-256 之後才安裝。
macOS · Linuxcurl -fsSL https://raw.githubusercontent.com/doggy8088/mgit/main/install.sh | sh
Windows PowerShell也支援 macOS 與 Linux 上的 PowerShell 7+。
Windows PowerShellirm https://raw.githubusercontent.com/doggy8088/mgit/main/install.ps1 | iex
npm · npx需要 Node.js 20 以上；套件內含 6 個平台的官方二進位，安裝時不執行任何程式碼（沒有 postinstall）。
npm · npxnpm install -g @willh/mgit
npm · npxnpx @willh/mgit
