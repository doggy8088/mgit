The classic case: scattered repositories, one directory

The app, a shared package, examples, deploy scripts: each its own repository, referring to each other by relative path, with no git submodule wiring them together. Clone them as sibling folders and one command drives them all.

mgit --listsee which repositories will be touched
mgitevery repository's status at once
mgit pullupdate them all in one run
mgit log --oneline -n 1the latest commit of each

mgit puts no files inside a repository and changes no relationship between them: it only sends the same command to every child directory. Pin versions with submodules; unify CI and releases with a monorepo.

How it finds the repositories

Level one only by default; sorted by name, identical on all three systems. --list shows what will be touched.

  1. The search starts in the current directory and walks down, one level by default (--depth goes deeper).
  2. A directory counts as a repository when it holds a .git directory or a .git file, so git worktree and submodules are recognised.
  3. Once a repository is found the search does not descend into it, so submodules and vendored projects are never counted twice.
  4. Symlinks are followed and counted under the name you see; the real directory behind them is visited only once, so link loops cannot hang the run.
  5. Results are sorted by name, ignoring case, and the order is identical on macOS, Linux and Windows.
  6. When nothing is found the run warns and exits with 1 (--allow-empty restores the old behaviour); if the current directory itself is a repository, git runs right there.

After the run: the summary and the exit code

The failing run names the repository and its code in the summary (✗ web-console (exit code 128)); the run ends on that first failing code.

Exit codesmgit 2.0.2
CodeMeaning
0Every repository succeeded (or nothing was found with --allow-empty)
1A repository failed, or no repository was found at all
2The command line could not be parsed
127git could not be started
130Interrupted with Ctrl+C (SIGINT / SIGTERM)
otherThe exit code of the first failing git invocation, reported unchanged

Install

One Rust binary, zero runtime dependencies; the official installers verify SHA-256 first.

macOS · LinuxPOSIX sh: detects the OS and CPU architecture, verifies SHA-256, then installs.

npm · npxNode.js 20+; the package ships the official binaries for six platforms and runs no code on install (there is no postinstall).

Why you can trust the reading

Numbers you can check, not adjectives.

platform binaries in npmno code runs on install

runtime dependenciesone Rust binary
SHA-256
per archivethe installers verify before installing
Transparent
mgit only claims the options it documents; anything else (-c, --git-dir…) goes straight to git.
No shell
Every git argument is passed as an array: no argument injection, no glob expansion.
Pipe safe
mgit … | head restores the default SIGPIPE behaviour and exits quietly instead of panicking.
Tests
cargo test --all-targets, clippy -D warnings and a 90% coverage floor, run on Ubuntu, macOS and Windows.
